# Ambysto Kit 0.2 — shared process reading and file-safety core

Ticket: APS-11 (`ambysto/ambysto-kit#14`, Plane APS-11), part of APS-2. Owner decision (2026-10-10): this moves into the Kit **before DevBox builds**; Space and Optimer switch to it later.

## Problem

Three Ambysto apps need the same two foundations, and today each keeps its own copy.

- **Reading processes** (who runs what, from where, with which files and sockets open, using how much CPU): Optimer wrote it for its monitor, Space copied and extended it for its in-use check, and DevBox needs it for ports, stopping and agent sessions. DevBox's accepted plan (ADB-2) writes no process-reading code of its own and waits for this release.
- **The file-safety gate** (never-touch list, real-path and firmlink handling, identity checks, in-use check): Optimer's original, and Space's extended version that two independent reviews hardened (firmlinks, identity by device + inode on every ancestor, Apple app data, cloud folders, mapped files). The copies already differ; a fix in one does not reach the other.

Every extra copy is a place where a safety fix can be missed.

## Outcome

Kit `0.2` adds two libraries next to `AmbystoLicense`. Apps depend on them by semver tag.

### 1. `AmbystoProcess` — reading processes (no deletion, no signals)

- Process list; per process: owner uid, parent, **identity (pid + start time)**, executable path, working directory, command line, open files, **listening sockets**, memory-mapped files. Every reader returns "unreadable" for processes of root or other users instead of failing.
- CPU and memory sampling: tick-to-nanosecond conversion, per-process CPU % from usage deltas keyed by identity (so pid reuse cannot corrupt a delta), physical footprint.
- Taken from Optimer's monitor and Space's safety folder, merged into one reviewed implementation.

### 2. `AmbystoSafety` — the file-safety gate shared by every app that moves files to the Trash

- **Suite-wide never-touch list** (Space's extended list: keys, keychains, photo libraries, Mail, Messages, iCloud Drive and other cloud drives, device and Time Machine backups, Apple app data, privacy database, main browser profiles, the Trash, system locations, agent transcripts), refused at selection and at delete time, including items that *contain* one.
- **Canonical paths** (symlinks resolved, case normalised, firmlinks collapsed) and **identity checks** (device + inode of the item and every ancestor; the item unchanged since it was shown).
- **In-use check**: processes whose executable, working directory or arguments are inside the item; open files; memory-mapped files (snapshot per session).
- **Full Disk Access** detection.
- **What stays in each app:** the *allowed roots* — which folders that app may change (Space: home items outside Library except Caches and Logs, app bundles, leftovers; Optimer: its cache catalog). The gate takes them as a rule the app supplies.

### 3. Specs

`docs/spec/process.md` (identity, readable vs unreadable, sampling definitions) and `docs/spec/safety.md` (the never-touch list, the gate's checks and their order, in-use rules), platform-neutral with Windows notes, so the Windows apps implement the same rules.

### Success criteria (measurable)

| # | Criterion | How it is checked |
|---|---|---|
| 1 | Every safety test from Space (firmlinks, never-touch per entry, identity, ancestors, Apple data, restricted items, in-use with real spawned processes, mapped files) and Optimer's monitor tests pass against the Kit libraries | `swift test` in the Kit |
| 2 | Listening sockets read through `AmbystoProcess` equal `lsof -nP -iTCP -sTCP:LISTEN` for the user's processes | comparison script |
| 3 | CPU % per process within 5 percentage points of `top` for the same readable processes over the same window; a reused pid never produces a negative or inflated delta | comparison script + unit test |
| 4 | DevBox builds its groups 3–7 on these libraries with no process-table reading of its own. *(Clarified 2026-10-10 after the plan review:* DevBox's `netstat` listing of root's and other users' listeners stays in DevBox — the data has no public API and the Kit libraries never spawn processes.) | DevBox build |
| 5 | Libraries are public API only, Swift 6 strict concurrency, 0 warnings; no deletion and no signal-sending API in either library | build + grep |
| 6 | The specs name no Swift types outside macOS notes | grep |

## Constraints

- Swift 6, macOS 14+, public Apple APIs only (libproc, sysctl, Security for signatures), no third-party dependencies.
- **The libraries never delete files and never send signals.** Deletion (each app's trasher) and stopping (DevBox's stopper) stay in the apps, so each app's single choke point stays provable in that app.
- Behaviour is taken from the reviewed Space version wherever Space and Optimer differ.
- Versioning: no Kit tag exists yet (the first waits for the license signing key on the Mac Studio). Kit 0.2 code merges to `main`; DevBox builds against a pinned Kit commit until tags exist, then moves to `from:` a tag before it ships.
- Everything on GitHub in English; feature branch and PR; Co-Authored-By trailer; tickets synced on GitHub and Plane; the Kit repo is public, so it holds no secrets.

## Out of scope

- Switching Space and Optimer to the Kit (their own tickets later, with no behaviour change and their tests green).
- App-specific rules: Space's allowed roots and leftover matcher, Optimer's cache catalog and app grouping for its monitor, DevBox's listener classifier and agent catalog.
- The trasher, the journal and Put back (they stay in Space for now).
- The brand tokens, floating mini bar and suite discovery (rest of APS-2).
