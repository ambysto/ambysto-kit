## Architecture

`AmbystoSafety` depends on `AmbystoProcess` (in-use check, `FileIdentity`); `AmbystoProcess` depends on nothing. Neither depends on `AmbystoLicense`; 0.2 is purely additive for license users.

### The one API change: allowed roots come from the app

Space's `SafetyPolicy.check(url, root: AllowedRoot, expected:)` hard-codes Space's three roots. In the Kit:

```
public struct SafetyContext: Sendable {          // what a rule may use
    public let homePath: String                  // canonical (firmlinks collapsed)
    public func canonical(_ path: String) -> String?
    public func visiblePath(_ path: String) -> String
}
public protocol AllowedRootRule: Sendable {
    /// Deleting: nil = inside this rule's roots; otherwise a plain refusal reason.
    func refusal(realPath: String, isDirectory: Bool, context: SafetyContext) -> String?
    /// Putting back: the destination does not exist yet. No default, so a rule never reuses its delete check by accident.
    func restoreRefusal(realPath: String, context: SafetyContext) -> String?
}
public struct SafetyGate: Sendable {
    public init(home: URL, additionalProtectedRoots: [String] = [])   // home-relative; can only ADD protection
    @_spi(Testing) public init(home: URL, additionalProtectedRoots: [String] = [],
                               systemRoots: [String], canonicalizer: PathCanonicalizer)   // tests only, visibly opted into
    public func check(_ url: URL, rule: some AllowedRootRule, expected: FileStamp?) -> SafetyDecision
    public func restoreDestinationRefusal(_ path: String, rule: some AllowedRootRule) -> String?
}
```

- Order inside `check` is unchanged from Space: exists → not a symlink → canonical path → unchanged since the scan → same volume → not `/` or home → **protection checks (Kit)** → **allowed-root rule (app)**. A rule runs only after every protection check passed, so no rule can widen protection.
- The suite-wide list no longer names `Library/Application Support/Ambysto Space`: each app passes its own data folder in `additionalProtectedRoots` (Space: its journal folder).
- **What stays in each app** (stated so the migration is mechanical): Space's application folders, `isWritable`, `leftoverFolders` and its three rules (`homeItem`, `applicationBundle` with its `Info.plist`/writability checks, `leftover` direct-child rule, each with its restore variant); Optimer's catalog allowlist (resolved through `context.canonical`, not `RealPath.resolve`, so firmlinked spellings match) and its hidden-tool-folder exception. Optimer only becomes stricter; refusal texts may come in a different order, so its tests that match reason text are updated at migration.
- **Name clashes at migration:** `ProcessReader`, `SafetyDecision`, `FileIdentity`, `NeverTouch`, `RealPath` exist in Space and Optimer too; each app deletes its copy when it switches (never both in one module).

## Files (in build order)

Branch `aps-11-kit-safety-core` → PR → `main`; one commit per group; Co-Authored-By trailer.

### 1. Specs — `docs/spec/process.md`, `docs/spec/safety.md`
- `process.md`: what a process record holds; "unreadable" instead of failure; identity = (pid, start time); CPU % per core from usage deltas between two samples of the same identity (first sample has none); listening sockets (TCP LISTEN, address and port, one record per socket); Windows notes (process snapshot, `GetExtendedTcpTable`, `GetProcessTimes`).
- `safety.md`: the never-touch list (Space's, item by item, macOS paths + Windows equivalents), the gate's checks and their order, "contains a protected item" rules, identity on every ancestor, the in-use rules (executable, working directory, arguments incl. relative ones, open files, mapped files snapshot every 10 s), the allowed-roots split (what an app must supply), and the restore-destination rules.

### 2. Package — `Package.swift`
Add library products `AmbystoProcess` and `AmbystoSafety`, their targets and test targets. No dependency changes.

### 3. `AmbystoProcess`
- Merge the two `ProcessReader`s: Space's (open files, mapped files, argv, cwd) + Optimer's rusage reader. BSD info also exposes `status` (so a zombie can count as exited) and uid. `arguments(_:)` reuses one buffer per reader instead of allocating `kern.argmax` (1 MiB here) per process.
- `ListeningSockets.read() -> [ListeningSocket]`, one pass over all readable processes: `{pid, fd, socketID (kernel socket handle, so processes sharing one socket — master and workers — are recognisable), port (network order converted with UInt16(bigEndian:)), family, address: .any / .loopback / .specific, ipv4, ipv6}`. An IPv6 socket carrying an IPv4-mapped address is decoded through the socket's version flags.
- `ProcessIdentity` replaces Optimer's `ProcessKey`. **Identity is the same process, not the same program:** pid and start time survive `exec`, so callers that act on a process re-check its executable path right before acting (spec `process.md`).
- `ProcessSampler`: a public `Sendable` struct with `mutating sample()`, the reader and the clock injectable; returns `[ProcessUsage]` (identity, ppid, uid, name, path, footprint, CPU %, disk B/s) and a hidden count. A counter that goes down (reuse, reset) gives no CPU value for that sample instead of a wrapped huge one. App grouping stays in Optimer.
- Tests: MachClock (Optimer's three); `parseProcArgs`; this process found with its path and cwd; **sockets bound in the test process itself on port 0** at 127.0.0.1, ::1, 0.0.0.0, :: and an IPv4-mapped address, each found with the right port and address class (no spawned `nc`, no fixed ports); a fake reader feeds the sampler a reused pid and a decreasing counter → no bad delta; a spawned busy loop shows CPU above 20% after two samples (generous, retried once, for a loaded 8 GB Mac); unreadable pids return `nil`.

### 4. `AmbystoSafety`
- Port Space's files; `SafetyPolicy` → `SafetyGate` + `AllowedRootRule` (above); `InUseChecker` uses `AmbystoProcess`.
- Port **all** of Space's safety tests, rewritten against `SafetyGate` with test rules that mirror Space's three roots (so every refusal path is still covered): every never-touch entry under every rule, Apple app data, firmlinked spelling of `~/Library/Keychains` on this Mac, identity on ancestors, changed/replaced files, 1970 dates, restricted items, symlinks, protected data inside a folder.
- **Direct gate tests** for what Space covered only through Put back (`DeletionTests`): restore destinations (protected place, outside the rule, missing parent, app bundle restore through `restoreRefusal`), and refusal at selection and at delete time.
- In-use tests with real `tail -f`, cwd and `mmap`, waiting by **polling** `openFiles` until the helper's file appears (no fixed sleeps).
- New: a rule that allows everything still cannot reach a never-touch item; `additionalProtectedRoots` protects an app's own folder; the public initialiser cannot remove system roots.

### 5. Proof scripts — `scripts/`
- An ordinary executable target `ProcessProbe` (SwiftPM has no test-only executables; it gets an automatic product but no app depends on it, and it is outside the libraries' grep) prints sockets or CPU as JSON.
- `compare-sockets.sh`: every (pid, address, port) line of the probe equals `lsof -nP -iTCP -sTCP:LISTEN` for the user's processes, three runs (criterion 2).
- `compare-cpu.sh`: the probe and `top -l 2 -s 2 -stats pid,cpu` run over the **same** 2 s window; only `top`'s second sample is used; the top 10 are taken among processes the probe can read; within 5 percentage points (criterion 3).

## Risks

| Risk | Catch |
|---|---|
| Generalising `SafetyPolicy` loses a check | The gate keeps Space's order; every Space test is ported; the "rule cannot widen protection" test. |
| Two `ProcessReader`s merged with a subtle difference (buffer sizes, EPERM handling) | Union of both test sets; unreadable → `nil` tests. |
| CPU % wrong by the tick factor or after pid reuse | MachClock tests; identity-keyed deltas; reuse test. |
| Listening sockets miss IPv6 or report ports in host order | Test with an IPv4 and an IPv6 listener; `lsof` comparison. |
| Flaky tests with spawned processes | Short-lived helpers with explicit waits, serialized suites (as in Space). |
| The libraries gain deletion or signals later | Proof grep on the two libraries: no `trashItem`, `removeItem`, `unlink`, `rmdir`, `remove(`, `rename`, `recycle`, `kill(`, `killpg`, `pthread_kill`, `sigqueue`, `proc_terminate`, `NSRunningApplication`, `Process(`, `posix_spawn`. |
| An app weakens protection through injection | Public initialiser can only add protected roots; system roots and canonicalizer only through `@_spi(Testing)`. |
| A circular module dependency | `FileIdentity` lives in `AmbystoProcess`; `AmbystoSafety` depends on it, never the reverse. |
| `exec` changes the program behind an identity | Spec rule and re-check of the executable path before acting (DevBox's stopper). |
| Kit has no tag yet; a pinned feature-branch commit may vanish after a squash merge | DevBox pins a commit **on `main`** after this PR merges; tags follow the license release. |
