# Ambysto Kit for Windows 0.3 — process reading (.NET)

Ticket: APS-39 (#70), part of APS-2 (#5). Follows APS-23 (#53, `Ambysto.Kit.License`) and APS-24 (#59, `Ambysto.Kit.Safety`). Its consumers are Ambysto DevBox, Ambysto Optimer and Ambysto Power for Windows (port order, owner decision 2026-10-19: Lean → Kit Process → DevBox → Optimer → Power → Tune).

## Problem

Three Windows apps of the suite need shared process reading before they can build:
- **DevBox** needs the process table, process identity `(pid, start time)` with executable-path re-check before stopping, parent-child trees (where Windows never updates a child's stored parent id when the parent exits, and the parent id may be reused), working directories, command lines and listening TCP sockets (`GetExtendedTcpTable`).
- **Optimer** needs per-process CPU %, private working set and I/O rates keyed by `(pid, start time)`.
- **Power** needs per-interval deltas (`CPU time`, `bytes read`, `bytes written`) and the monotonic sampling interval (excluding sleep), with wakeups and energy reported as *absent* (never invented as `0`) so Power falls back to CPU time as `docs/spec/process.md` specifies.

`docs/spec/process.md` is platform-neutral, with a four-line Windows note written during the macOS 0.2/0.3 work. Auditing `docs/spec/process.md` against probes on the Windows 11 test machine (2026-10-19 and 2026-10-24, standard user over SSH in session 0 and in the console session; saved on the test machine under `probes/kit-process/p2`–`p8`) showed several places where the Windows note was incomplete or needed an explicit product decision:

- **Snapshot source (`p3.out`, `p4-sdk-header.out`):** the spec's Windows note named `CreateToolhelp32Snapshot` + `GetProcessTimes`. `NtQuerySystemInformation(SystemProcessInformation)` (`class 5`, 256-byte `SYSTEM_PROCESS_INFORMATION` header on x64) returns in a single system call — without opening any process handle — every live process's `UniqueProcessId`, `InheritedFromUniqueProcessId`, short `ImageName`, `CreateTime` (100-ns `FILETIME`, verified identical to `GetProcessTimes` in `p3.out`), `UserTime` and `KernelTime` (100-ns ticks, identical to `GetProcessTimes`), `WorkingSetPrivateSize` (private working set in bytes at offset 8), `ReadTransferCount` and `WriteTransferCount` (bytes read and written at offsets 232 and 240, verified identical to `GetProcessIoCounters` in `p3.out`), `SessionId` (offset 100) and `NumberOfThreads` (offset 4). Because `CreateTime` and the counters sit in the same kernel snapshot entry, they are captured together in one pass.
- **Access by a standard user (`p2.out`, `p5-elevation-and-cwd.out`, `p6-admin-and-elevated.out`, `p8-complete-facts.out`):** WMI and `Get-NetTCPConnection` are denied to a standard user over SSH (`Cannot connect to CIM server. Access denied`, `p8-complete-facts.out`), whereas `netstat -ano -p tcp` and `netstat -ano -p tcpv6` succeed, so both the library and its tests must avoid WMI/CIM. `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` fails with `ERROR_ACCESS_DENIED (5)` on `SYSTEM` and service processes (`p2.out`), and succeeds on the current user's own non-elevated processes across sessions (`session 0` and the interactive desktop session). On a readable handle, `QueryFullProcessImageNameW` reads the executable path, `OpenProcessToken(TOKEN_QUERY)` reads the owner SID (`TokenUser`) and elevation state (`TokenElevation`, `TokenIsElevated`: `0` on non-elevated `p5-elevation-and-cwd.out`, `1` on elevated `p6-admin-and-elevated.out`), and `NtQueryInformationProcess(ProcessCommandLineInformation = 60)` reads the command line with `PROCESS_QUERY_LIMITED_INFORMATION` alone. `CommandLineToArgvW` splits a non-empty command line, but when given `""` or `"   "` it returns the calling process's own module path or `[""]` (`p8-complete-facts.out`), so empty or whitespace-only command lines must not be passed to `CommandLineToArgvW`.
- **Working directory and WOW64 (`p5-elevation-and-cwd.out`):** Windows has no API like `ProcessCommandLineInformation` for another process's working directory; reading it requires `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ)` and reading `CurrentDirectory.DosPath` from the 64-bit `PEB` (`PebBaseAddress + 0x20` → `RTL_USER_PROCESS_PARAMETERS + 0x38`, the same layout `Ambysto.Kit.Safety` uses in `Internal/InUse.cs`). The PEB string carries a trailing backslash (`C:\Users\…\`, `p5-elevation-and-cwd.out`). For a 32-bit (WOW64) process (`IsWow64Process2` reports `processMachine != 0`, e.g. `0x014C` for `C:\Windows\SysWOW64\cmd.exe`), `QueryFullProcessImageNameW` and `ProcessCommandLineInformation` still succeed.
- **Parent PID reuse and orphans (`p8-complete-facts.out`):** Windows records `InheritedFromUniqueProcessId` when a process is created and never clears it when the parent exits (`p8-complete-facts.out`: after parent `8396` exited and left `SystemProcessInformation`, child `8936` still reported `InheritedFromUniqueProcessId = 8396`); that PID can later be assigned to a newer, unrelated process.
- **Exited processes and open handles (`p7-exited-handle.out`, `p8-complete-facts.out`):** once a process exits on Windows 11, it disappears from `SystemProcessInformation` (`inSPI = False`) even while another process still holds a handle to it (`OpenProcess` still succeeds while the handle is held, and `GetProcessTimes` reports `exitTime != 0`, `p7-exited-handle.out`); once the last handle closes, `OpenProcess` fails with `ERROR_INVALID_PARAMETER (87)` (`p8-complete-facts.out`). If caught mid-termination in `SystemProcessInformation`, `NumberOfThreads` is `0`.
- **Listening sockets (`p2.out`, `p8-complete-facts.out`):** `GetExtendedTcpTable` with `TCP_TABLE_OWNER_PID_LISTENER` (`class 3`) for `AF_INET` (`MIB_TCPROW_OWNER_PID`, 24 bytes) and `AF_INET6` (`MIB_TCP6ROW_OWNER_PID`, 56 bytes, `dwLocalScopeId` at offset 16 in host byte order and `dwLocalPort` at offset 20 in network byte order in the first two bytes; `p2.ps1` had read offset 24 by mistake, corrected and verified in `p8-complete-facts.out` including a link-local listener `fe80::…%14`) returns every listening TCP socket with its owning PID, including system listeners (`pid = 4` on ports 139 and 445). Unlike macOS (`PROC_PIDFDSOCKETINFO`), Windows exposes no socket handle identifier through `GetExtendedTcpTable`, so shared master/worker sockets cannot be grouped by handle id.
- **Monotonic clock (`p8-complete-facts.out`):** `QueryUnbiasedInterruptTime` returns unbiased interrupt time in 100-ns units (excluding sleep/hibernation).

Owner decisions (2026-10-24, answers `1A 2A 3A 4A 5A 6A` to the Windows question batch):
1. **Elevated processes of the current user (1A):** treated as **unreadable** (`TokenIsElevated != 0`), like `root` on macOS; DevBox never targets an elevated process.
2. **Processes of other users, SYSTEM or elevated processes (2A):** expose only `Identity` `(pid, creationTime)`, validated `ParentProcessId`, short `Name` and `SessionId` (read from `SystemProcessInformation` without opening a handle), while `OwnerSid`, `ExecutablePath`, `WorkingDirectory`, `CommandLine`, `Arguments` and `Usage` (CPU, memory, I/O) are **unreadable** (`null`), matching macOS. DevBox still gets the short name (`"System"`, `"sshd.exe"`, …) for another user's listening socket.
3. **Per-process open files and memory-mapped files (3A):** **not implemented** in `Ambysto.Kit.Process` on Windows. No Windows app of the suite lists all files held by each process, and file-centric in-use checking ("which processes hold this file or folder?") is already in `Ambysto.Kit.Safety.InUseChecker` (via `FileProcessIdsUsingFileInformation` and the Restart Manager, which avoids enumerating system handles that can block on named pipes).
4. **Working directory of 32-bit (WOW64) processes (4A):** reported as **unreadable** (`null`) when `IsWow64Process2` reports a WOW64 process (`processMachine != 0`), matching `Ambysto.Kit.Safety` (64-bit PEB only); all other readable fields (`ExecutablePath`, `CommandLine`, `Arguments`, `OwnerSid`, `Usage`) are still read.
5. **Bytes read and written (5A):** reported from `ReadTransferCount` and `WriteTransferCount` (`SystemProcessInformation` / `IO_COUNTERS`), with an explicit spec note that Windows counts all process I/O transfer bytes (file, network and device/pipe I/O), not disk-only bytes.
6. **Packaging (6A):** a third NuGet package, **`Ambysto.Kit.Process`**, packed and pushed from the shared `windows-v0.3.0` tag together with `Ambysto.Kit.License` and `Ambysto.Kit.Safety`.

Additional audit points confirmed with the batch (2026-10-24):
- Snapshot via `NtQuerySystemInformation(SystemProcessInformation)` (replacing `CreateToolhelp32Snapshot` in the spec's Windows note).
- A parent PID from the snapshot is accepted only when the parent is present among the surviving (live, non-skipped) entries of the same snapshot (`parentPid > 0`, `parentPid != pid`) and its `StartTimeTicks <= child.StartTimeTicks`; otherwise `ParentProcessId` is `null`.
- Listening sockets have no `SocketId` on Windows (one record per row in `GetExtendedTcpTable` for a readable process, plus a separate all-listeners query for DevBox's port table where unreadable owners show by short name from the process snapshot).
- Command line keeps the raw string from `ProcessCommandLineInformation` and provides an argument list split by `CommandLineToArgvW` (documented as the shell's approximate split, since on Windows the raw string is authoritative; empty or whitespace-only command lines yield `[]` without calling `CommandLineToArgvW`).
- Exited processes (`NumberOfThreads == 0` in the snapshot, or `ExitTime != 0` / `ERROR_INVALID_PARAMETER` when opened) count as exited and are excluded, never returned as zombies. `PID 0` (`System Idle Process`) is excluded.
- Owner is the user SID string (`S-1-5-…`), alongside `SessionId`.
- Memory footprint is `WorkingSetPrivateSize` (private working set in bytes).
- Monotonic sampling clock is `QueryUnbiasedInterruptTime` (100-ns units converted to nanoseconds; does not advance while the system sleeps). Idle wakeups, interrupt wakeups and energy are `null` (*absent*, never `0`).
- Choke points (`scripts/windows-choke-points.sh` extended to `Ambysto.Kit.Process`): no process termination, signalling, suspension, debugging, remote threads, memory writes, process spawning or file/registry writes.

## Outcome

`windows-v0.3.0` of `ambysto/ambysto-kit`: a third .NET library, **`Ambysto.Kit.Process`** (namespace `Ambysto.Kit.Processes`, avoiding a C# name collision with `System.Diagnostics.Process`), in `windows/`, built from `docs/spec/process.md` (with the Windows notes below) and never from the Swift code. It reads; it never terminates, signals, suspends, spawns or modifies anything.

### 1. Process records and identity (spec "A process record" and "Identity", Windows form)

- **Identity (`ProcessIdentity`):** `(ProcessId, StartTimeTicks)` where `ProcessId` (`int`) > 0 and `StartTimeTicks` (`long`) is the process's Windows creation time (`FILETIME`, 100-ns ticks since 1601-01-01 UTC).
- **Snapshot (`ProcessReader.ReadSnapshot()` → `ProcessSnapshot`):** reads `NtQuerySystemInformation(SystemProcessInformation)` and returns `Processes` (`IReadOnlyList<ProcessRecord>`, holding all surviving readable and unreadable processes) and `UnreadableProcessCount` (`int`).
  - **Pass 1 — per-entry liveness, counters and handle metadata:**
    - `PID 0` (`System Idle Process`) and any entry with `NumberOfThreads == 0` (already terminated) are skipped.
    - In `SystemProcessInformation`, the kernel captures `UniqueProcessId`, `CreateTime` (`StartTimeTicks`) and the usage counters (`WorkingSetPrivateSize`, `UserTime`, `KernelTime`, `ReadTransferCount`, `WriteTransferCount`) atomically in one entry. To bind the handle-based metadata to that snapshot entry and guard against mid-read exit or PID reuse (spec "Sampling" rule 7):
      1. Opens the process with `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)`.
      2. If `OpenProcess` fails with `ERROR_INVALID_PARAMETER (87)` (the process exited between the snapshot and `OpenProcess`), the entry is **skipped** (neither returned nor counted as unreadable).
      3. If `OpenProcess` fails with `ERROR_ACCESS_DENIED (5)` (or any other non-exit error), the process is **unreadable** (`IsReadable = false`, `UnreadableProcessCount` incremented by 1; see fields below).
      4. If `OpenProcess` succeeds, calls `GetProcessTimes` on the handle **before** reading metadata: if `GetProcessTimes` fails, reports `ExitTime != 0` (already exited while a handle was held open), or reports `CreationTime != snapshot.CreateTime` (the PID was reused between the snapshot and `OpenProcess`), the entry is **skipped**.
      5. Opens the process token with `OpenProcessToken(TOKEN_QUERY)` and reads `TokenUser` (owner SID) and `TokenElevation` (`TokenIsElevated`). If `OpenProcessToken` or `GetTokenInformation` fails, or `TokenUser` SID != current user's SID, or `TokenIsElevated != 0` (decision 1A), the process is **unreadable** (`IsReadable = false`, `UnreadableProcessCount` incremented by 1).
      6. Otherwise the process is **readable** (`IsReadable = true`): reads `ExecutablePath`, `CommandLine`/`Arguments` and `WorkingDirectory` (below), then calls `GetProcessTimes` on the handle **after** reading metadata (and, in `IProcessSnapshotSource`, compares pre-read `StartTimeTicks` with post-read `StartTimeAfterTicks` and `HasExitedAfterRead`). If the process exited during the metadata read (`ExitTime != 0` / `HasExitedAfterRead`) or its start time changed (`StartTimeAfterTicks != StartTimeTicks`), the entry is **skipped** so partial or teardown PEB data is never returned.
    - **Unreadable record fields (decisions 1A, 2A):** `IsReadable = false`, `Identity = (pid, snapshotCreateTime)`, `ParentProcessId` (filled in Pass 2), `Name` (short image name from `SystemProcessInformation.ImageName`) and `SessionId`, while `OwnerSid`, `ExecutablePath`, `WorkingDirectory`, `CommandLine`, `Arguments` and `Usage` are `null`.
    - **Readable record fields:** `IsReadable = true`, `Identity`, `ParentProcessId` (filled in Pass 2), `Name`, `SessionId`, plus:
      - `OwnerSid`: the user SID string (`S-1-5-…`).
      - `ExecutablePath`: from `QueryFullProcessImageNameW` with flags `0` (Win32 DOS path; `null` if the query fails).
      - `CommandLine` and `Arguments`: `CommandLine` is the raw string from `NtQueryInformationProcess(ProcessCommandLineInformation = 60)` (`null` if the query fails). When `CommandLine` is `null`, `Arguments` is `null`; when `CommandLine` is empty or whitespace-only (`string.IsNullOrWhiteSpace`), `Arguments` is `Array.Empty<string>()` (`CommandLineToArgvW` is not called); otherwise `Arguments` (`IReadOnlyList<string>`) is the list returned by `CommandLineToArgvW`.
      - `WorkingDirectory`: when `IsWow64Process2` reports a native 64-bit process (`processMachine == 0`), read from the 64-bit PEB (`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION | PROCESS_VM_READ)`, `PebBaseAddress + 0x20` → `RTL_USER_PROCESS_PARAMETERS + 0x38`), normalized by stripping a leading `\\?\` if present and trimming a trailing `\` except on a drive root (`C:\` stays `C:\`, `C:\Users\alice\` becomes `C:\Users\alice`); when `processMachine != 0` (WOW64, decision 4A) or the PEB read fails, `null` (the process itself stays readable).
      - `Usage` (`ProcessCounters`): `MemoryBytes` (`WorkingSetPrivateSize`, `long`), `CpuTimeNanoseconds` (`checked((UserTime + KernelTime) * 100)`, `long`), `BytesRead` (`(long)ReadTransferCount`), `BytesWritten` (`(long)WriteTransferCount`), and `IdleWakeups`, `InterruptWakeups`, `EnergyNanojoules` all `null` (absent on Windows).
  - **Pass 2 — parent validation across surviving entries:** for each surviving entry (readable or unreadable) with raw `InheritedFromUniqueProcessId > 0` and `!= Identity.ProcessId`, looks up that parent PID among the **surviving entries** of the same snapshot; if present and `parent.Identity.StartTimeTicks <= child.Identity.StartTimeTicks`, `ParentProcessId` is that PID, otherwise `null` (the parent exited, was skipped, or its PID was reused by a younger process).
- **Single-process re-check (`ProcessReader.Read(ProcessIdentity)` and `ProcessReader.ExecutablePath(ProcessIdentity)`):** opens `identity.ProcessId` with `PROCESS_QUERY_LIMITED_INFORMATION`, verifies `ExitTime == 0` and `CreationTime == identity.StartTimeTicks`, verifies same user and `TokenIsElevated == 0`, and returns the `ProcessRecord` (even if an optional field such as `WorkingDirectory` or `ExecutablePath` is `null`) or `null` if the process exited, its PID was reused or it is unreadable. `ExecutablePath(ProcessIdentity)` returns `Read(identity)?.ExecutablePath`.

### 2. Listening sockets (spec "Listening sockets", Windows form)

- Reads `GetExtendedTcpTable` with `TCP_TABLE_OWNER_PID_LISTENER` (`class 3`) for `AF_INET` (`MIB_TCPROW_OWNER_PID`, 24 bytes) and `AF_INET6` (`MIB_TCP6ROW_OWNER_PID`, 56 bytes). Rows with `dwOwningPid == 0` are ignored.
- Each `ListeningSocket` record has:
  - `ProcessId` (`int`), `ProcessIdentity` (`ProcessIdentity?`), `ProcessName` (`string?`), `IsOwnerReadable` (`bool`)
  - `Port` (`ushort`, host byte order, decoded as `(ushort)((byte0 << 8) | byte1)` from the first two bytes of `dwLocalPort` — offset 8 in `MIB_TCPROW_OWNER_PID`, offset 20 in `MIB_TCP6ROW_OWNER_PID` — ignoring the upper 16 bits)
  - `Family` (`SocketAddressFamily.IPv4` or `IPv6`)
  - `Address` (printable local address string from `new IPAddress(addrBytes)` for IPv4 and `new IPAddress(addrBytes16, dwLocalScopeId)` for IPv6, where `dwLocalScopeId` at offset 16 is in host byte order, formatting `fe80::…%<scope>` when `dwLocalScopeId != 0` and omitting `%0` when `0`)
  - `AddressClass`:
    - `SocketAddressClass.Any` for `0.0.0.0` (`IPAddress.Any`) and `::` (`IPAddress.IPv6Any` with `ScopeId == 0`)
    - `SocketAddressClass.Loopback` for `127.0.0.0/8` (`IPAddress.IsLoopback`), `::1` (`IPAddress.IPv6Loopback`), and IPv4-mapped IPv6 loopback (`ip.IsIPv4MappedToIPv6 && IPAddress.IsLoopback(ip.MapToIPv4())`)
    - `SocketAddressClass.Specific` for every other address (including link-local `fe80::…%<scope>`)
  - `SocketId`: `ulong?`, always `null` on Windows (not provided by `GetExtendedTcpTable`; documented in the spec).
- Provides two queries over a `ProcessSnapshot`:
  - `ListeningSockets.ReadForReadableProcesses(ProcessSnapshot)`: returns only rows whose `dwOwningPid` matches a **readable** (`IsReadable == true`) process in the snapshot, with its non-null `ProcessIdentity`, `ProcessName` and `IsOwnerReadable = true` (matching the spec's "Every TCP socket in the LISTEN state of a readable process").
  - `ListeningSockets.ReadAll(ProcessSnapshot)`: returns every row with `dwOwningPid > 0`; when `dwOwningPid` matches a surviving entry in the snapshot (readable or unreadable), populates `ProcessIdentity`, `ProcessName` and `IsOwnerReadable = entry.IsReadable`; when the owner exited between the snapshot and the TCP table read (not in `snapshot`), `ProcessIdentity = null`, `ProcessName = null` and `IsOwnerReadable = false`.

### 3. Sampling (spec "Sampling", Windows form)

- `ProcessSampler` takes snapshots over `IProcessSnapshotSource` and a monotonic clock (`IMonotonicClock`, default `QueryUnbiasedInterruptTime` × 100 ns, which does not advance while the computer sleeps).
- `ProcessSampler.Sample()` returns a `ProcessSample`:
  - `Processes` (`IReadOnlyList<SampledProcess>`): **readable processes only** from the current snapshot (each carrying its `ProcessRecord` with non-null `Usage`, plus `Deltas` and rates below),
  - `AllProcesses` (`IReadOnlyList<ProcessRecord>`): all surviving processes from the current snapshot (readable and unreadable, so callers that need the full table and sampling in one tick do not take two snapshots),
  - `UnreadableProcessCount` (`int`), and
  - `TimestampNanoseconds` (`long`).
- Keyed by `ProcessIdentity` (`(ProcessId, StartTimeTicks)`), never by PID alone.
- For each readable process in the current sample:
  - **First sample of an identity**, or **zero/negative interval** (`intervalNanoseconds <= 0`): `Deltas` is `null`, and all rates (`CpuPercent`, `BytesReadPerSecond`, `BytesWrittenPerSecond`, `IdleWakeupsPerSecond`, `InterruptWakeupsPerSecond`) are `null`.
  - **All-or-nothing rule:** if any cumulative counter present in both samples (`CpuTimeNanoseconds`, `BytesRead`, `BytesWritten`, or — in seam tests that supply them — `IdleWakeups`, `InterruptWakeups`, `EnergyNanojoules`) went down (`current < previous`), `Deltas` is `null` and all rates are `null` for that process in that sample.
  - Otherwise:
    - `UsageDeltas`: `IntervalNanoseconds`, `CpuTimeNanoseconds`, `BytesRead`, `BytesWritten`, `IdleWakeups` (`null` on Windows; present when both samples have it), `InterruptWakeups` (`null` on Windows; present when both samples have it), `EnergyNanojoules` (`null` on Windows; present only when both samples have it, `0` stays `0`).
    - Rates: `CpuPercent = 100.0 * deltaCpuNs / intervalNs` (per core: one fully busy core = `100.0`), `BytesReadPerSecond = deltaRead * 1e9 / intervalNs`, `BytesWrittenPerSecond = deltaWritten * 1e9 / intervalNs`, `IdleWakeupsPerSecond` (`deltaIdle * 1e9 / intervalNs` when present, `null` on Windows), `InterruptWakeupsPerSecond` (`deltaInterrupt * 1e9 / intervalNs` when present, `null` on Windows).
    - `IsZombie` is always `false` on Windows (exited processes are excluded).
- **Internal seams** (test-only, `InternalsVisibleTo` the test assembly, HARD like APS-24's seams): `IProcessSnapshotSource`, `ITcpTableSource` and `IMonotonicClock` so acceptance and unit tests can deterministically inject reused PIDs, pre/post start-time mismatches, mid-read exits, counter decreases, zero intervals, sleep gaps, elevated tokens, WOW64 processes and fake wakeup/energy counters, alongside real-process tests in the VM.
