# Plan — Ambysto Kit 0.1.0: offline license keys

Intent: [`2026-10-10-kit-0.1-license.md`](2026-10-10-kit-0.1-license.md) (approved 2026-10-10). Self-contained: an implementing agent reads this file and the intent only.

## Verified in a spike (2026-10-10, macOS 26.6.2)

- CryptoKit `P256.Signing`: signature `rawRepresentation` is 64 bytes (`r‖s`, the IEEE P1363 form .NET reads with `DSASignatureFormat.IeeeP1363FixedFieldConcatenation`); public key `rawRepresentation` 64 bytes (`x‖y`). Sign + verify ≈ 3 ms.
- A 30-byte payload + 64-byte signature = 94 bytes → 151 Base32 characters → `AMB-` + 31 groups of five.
- `hdiutil create -encryption AES-256 -stdinpass -fs APFS -size 10m` and `attach -stdinpass` work without a terminal prompt; a written file is not visible in the image bytes. 1 MB is too small for APFS.
- A Keychain generic password created through `SecAccessCreate` with an **empty trusted-application list** compiles cleanly in C with the deprecation warning silenced in that file only. (Its prompt is verified by the owner at Proof 8; the agent does not trigger GUI prompts.)

## Format (normative; copied into `docs/spec/license.md`)

**Payload (version 1), big-endian:**

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | format version = `1` |
| 1 | 1 | signing key id (which trusted public key verifies it); `0` = the published test key |
| 2 | 8 | license key id (random) — what the revocation list names, written as 16 lowercase hex characters |
| 10 | 2 | issued, days since 2026-01-01 |
| 12 | 2 | updates until, days since 2026-01-01; `0` = for life |
| 14 | 1 | seats (informational) |
| 15 | 2 | products bitmask: bit 0 `optimer`, 1 `steady`, 2 `space`, 3 `devbox`, 4 `power`, 5 `tune`, 6 `guard`; bits 7–15 reserved (must be 0 in v1) |
| 17 | 1 | licensee length *n* (1–64) |
| 18 | *n* | licensee, UTF-8 (NFC) |

**Signature:** ECDSA P-256 with SHA-256 over `"AMBYSTO-LICENSE-1"` (ASCII, domain separation) followed by the payload; 64-byte raw `r‖s`.

**Text:** `AMB-` + Crockford Base32 (`0-9 A-Z` without `I L O U`, no padding) of `payload ‖ signature`, in groups of five joined by `-`. Parsing: drop a leading `AMB` (any case), remove every character that is not a letter or digit, uppercase, map `O→0`, `I L→1`, decode. Anything else → "malformed".

**File:** `.ambystokey` = the text form in UTF-8, optionally followed by a newline; UTI `com.ambysto.license-key`, conforming to `public.plain-text`.

**Verification order:** decode → length and version → reserved bits zero → licensee length → known signing key id → signature → revoked key id. Each failure has one reason string.

## Files (in build order)

Each group is one commit on `aps-10-kit-license`, merged by PR. Commit messages end with the Co-Authored-By line.

### 1. Spec — `docs/spec/license.md`, `docs/spec/license-test-vectors.json`
- The format above, the product registry, rotation and revocation rules, the `.ambystokey` file, the reason strings, and a Windows note (.NET `ECDsa.ImportParameters` with the raw public key; `VerifyData(…, HashAlgorithmName.SHA256, DSASignatureFormat.IeeeP1363FixedFieldConcatenation)`).
- The **test signing key** (id 0): private and public key in hex, labelled "published on purpose; never trusted by release builds".
- Test vectors (generated in group 4, committed): valid single-app, valid suite, valid with `updatesUntil`, lowercase + spaces + line breaks form, tampered payload byte, tampered signature byte, unknown signing key id, revoked key id, reserved bit set, version 2, truncated, empty, non-Base32 characters. Each: input text and expected result (fields or reason).

### 2. Package — `Package.swift` (swift-tools 6.0, macOS 14, Swift 6)
- Library product `AmbystoLicense` (target `AmbystoLicense`): what apps import.
- Executable product `ambysto-license` (target `LicenseTool` + C target `KeychainACL`): the owner's tool. Not a dependency of any app.
- Test target `AmbystoLicenseTests`. No third-party dependencies.

### 3. Library — `Sources/AmbystoLicense/`
- `Product.swift` — the registry (`optimer`…`guard`), bit positions, `id` strings.
- `Base32.swift` — Crockford encode/decode with the parsing rules above.
- `LicensePayload.swift` — encode/decode of the payload; dates as days since 2026-01-01.
- `License.swift` — `licensee`, `products`, `keyID`, `issued`, `updatesUntil`, `seats`, `signingKeyID`; `covers(_ product:)`, `allowsUpdates(builtOn:)`.
- `TrustedKeys.swift` — signing key id → raw public key. `TrustedKeys.production` holds id 1 (filled in by the owner at Proof 7, see Risks); `TrustedKeys.test` holds id 0 and is internal to tests and the tool's test mode.
- `Revocations.swift` — revoked key ids for this release (empty in 0.1.0).
- `LicenseVerifier.swift` — `init(trusted: TrustedKeys = .production, revoked: Set<String> = Revocations.all)`; `verify(_ text: String) -> Result<License, LicenseError>`; `verify(fileAt: URL)`; files over 4 KB are refused before reading.
- `LicenseError.swift` — `malformed`, `unsupportedVersion`, `unknownSigningKey`, `badSignature`, `revoked`, each with a plain message ("This key was mistyped or damaged", …).
- `LicenseSigner.swift` (internal to the tool and tests): builds a payload, signs it, returns the text form.

### 4. Tool — `Sources/LicenseTool/`, `Sources/KeychainACL/`
Commands (`swift run ambysto-license <command>`, or the built binary):
- `new-signing-key [--id 1]` — generates the key, stores the private half through **one storage step** (`SigningKeyStore`), prints the public key in hex for `TrustedKeys.production`, then creates the backup: asks for a passphrase twice with no echo (`readpassphrase`), creates the AES-256 image with `-stdinpass`, writes the key, detaches, and prints the image path. Refuses to overwrite an existing key.
- `import-signing-key <image>` — asks for the passphrase, attaches read-only, stores the key through `SigningKeyStore`, detaches.
- `issue --licensee <name> --products space[,optimer…] [--seats 3] [--updates-until YYYY-MM-DD] [--out file.ambystokey]` — reads the key (macOS asks for the login password), signs, prints the `AMB-` text, writes the file, appends one line to the ledger `~/Library/Application Support/Ambysto License/ledger.csv` (key id, date, licensee, products, seats, updates-until). Verifies the new key with `LicenseVerifier` before printing it.
- `public-key` — prints the stored key's public half (also asks for the password).
- `test-vectors --out docs/spec/license-test-vectors.json` — uses only the published test key.
- `SigningKeyStore` (one protocol, the only place keys are stored or read): `KeychainStore` — `KeychainACL.c` adds the item with an empty trusted-application list (`SecAccessCreate`; the C file silences that one deprecation), reads with `SecItemCopyMatching`. A `FileStore` exists **only in DEBUG builds** for automated tests with the test key.
- The private key never touches stdout, stderr, logs, arguments or temporary files; it lives in memory only while signing.

### 5. Tests — `Tests/AmbystoLicenseTests/`
- Every vector in `license-test-vectors.json` gives its documented result (criterion 1).
- Round trip: encode → text → lowercase/spaces/newlines → decode (criterion 4).
- Fuzz: 20,000 random strings and 20,000 single-byte mutations of a valid key never crash and never verify (criterion 3).
- Products: a suite key covers each listed product and nothing else; `allowsUpdates(builtOn:)` before and after `updatesUntil`; for-life keys allow any date.
- Timing: verification under 10 ms (criterion 6).
- Tool, DEBUG `FileStore` + test key: `issue` output verifies; the ledger line is written; nothing but the license reaches stdout.

### 6. Space adoption (in `ambysto/ambysto-space`, branch `asp-2-…`, its own commit and PR)
- `Package.swift`: `.package(url: "https://github.com/ambysto/ambysto-kit.git", from: "0.1.0")`, product `AmbystoLicense`.
- `KitLicenseVerifier` adapts `LicenseVerifier` to Space's `LicenseVerifying` seam and becomes `EntitlementStore`'s default; `PendingLicenseVerifier` is deleted.
- `Info.plist`: imports UTI `com.ambysto.license-key` and declares `.ambystokey` as a document type (role Viewer), so double-clicking a key file opens Space; the app activates it through the same `activate` path and shows the result.
- Space's Proof 12 runs with keys from `issue`.

### 7. Release
- The owner runs `new-signing-key` on the issuing Mac and pastes the printed public key into `TrustedKeys.production` (id 1) in a commit; then tag `v0.1.0`.

## Risks

| Risk | Catch |
|---|---|
| The private key leaks into the repo, a log, the shell history or an argument | Never printed; read with `readpassphrase`/Keychain only; `git grep` for the hex of the production public key's private half is impossible to check, so the check is structural: grep the tool for `print`/`FileHandle.standardError` uses on key data, and a secret scan (`git log -p` grep for 64-hex runs other than the published test key). |
| A coding agent reads the Keychain item | Empty trusted-app ACL → password prompt on every read (Proof 8); agents run under a separate standard user on the issuing Mac (intent). Clicking "Always Allow" would add the tool to the ACL: the tool prints a one-line reminder to choose "Allow"; ad-hoc rebuilds change the tool's identity, which drops that trust anyway. |
| Release builds trust the published test key | `TrustedKeys.test` is internal; a test asserts `TrustedKeys.production` has no id 0 and that a test-key license fails with `unknownSigningKey` under `.production`. |
| `v0.1.0` tagged before the production key exists | Group 7 order; Proof 7 checks `TrustedKeys.production` is non-empty at the tag. |
| ECDSA signatures differ each run (random nonce), so vectors cannot be regenerated identically | Vectors are generated once and committed; tests verify, they never compare signatures. |
| Windows reads the signature in DER instead of raw | Spec states raw `r‖s` and the exact .NET call. |
| Licensee names with accents compare differently | NFC normalisation before encoding; vector with Vietnamese diacritics. |
| A huge or binary `.ambystokey` file | 4 KB limit before reading; non-text → malformed. |
| SwiftPM cannot fetch the private Kit repo in Space | The `ambysto` account's GitHub credentials are used by git; checked by Space's build at Proof 7. |
| Losing the Mac and the backup | Rotation: new key id 2 in the next Kit release; issued keys keep working (intent). |

## Proof

1. `swift build -c release` in the Kit: 0 warnings.
2. `swift test`: all pass, including every vector, fuzz and timing.
3. Secret checks: no 64-hex string in the repo or its history except the published test key; the tool's source never writes key data to output.
4. `swift run ambysto-license test-vectors` regenerates a file whose every entry verifies to the same result (signatures may differ).
5. Development issuing with the DEBUG file store: an issued key verifies, the ledger has the line, stdout has only the license.
6. `docs/spec/license.md` has no Swift types outside "macOS note" lines; the Windows note names the .NET calls.
7. **Owner:** run `new-signing-key` on the issuing Mac (Proof of criteria 8–9 below), paste the public key, tag `v0.1.0`; Space builds against `from: "0.1.0"` with all tests green.
8. **Owner:** `issue` asks for the login password; cancelling the prompt makes it fail with no output.
9. **Owner:** `import-signing-key` on a second Mac or a fresh user restores the key; a license issued there verifies.
10. **Owner + agent:** Space Proof 12 with Wi-Fi off — a `space` key and a suite key unlock Pro without a restart; an `optimer` key is refused; double-clicking an `.ambystokey` file activates.
11. Independent review of the diff against the intent and this plan.
