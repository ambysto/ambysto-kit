# Plan — Ambysto Kit 0.1.0: offline license keys

Intent: [`2026-10-10-kit-0.1-license.md`](2026-10-10-kit-0.1-license.md) (approved 2026-10-10). Self-contained: an implementing agent reads this file and the intent only. Revised after an independent technical review (12 findings, all folded in; log at the end).

## Verified in a spike (2026-10-10, macOS 26.6.2)

- CryptoKit `P256.Signing`: signature `rawRepresentation` is 64 bytes (`r‖s`, the IEEE P1363 form); public key `rawRepresentation` 64 bytes (`x‖y`). Sign + verify ≈ 3 ms. CryptoKit also accepts the high-S twin `(r, n−s)` of a valid signature (reviewer, verified).
- `hdiutil create -encryption AES-256 -stdinpass -fs APFS -size 10m` and `attach -stdinpass` work without a terminal prompt; the stdin bytes are the passphrase **exactly** (a trailing newline becomes part of it — reviewer, verified); a written file is not visible in the image bytes; 1 MB is too small for APFS; APFS images mount with `noowners` unless told otherwise (reviewer, verified).
- A Keychain generic password created through `SecAccessCreate` with an empty trusted-application list compiles cleanly in C with that one deprecation silenced. Its prompt is verified by the owner (Proof 8); the agent never triggers GUI prompts.
- Swift's `Character.isLetter/isNumber` accept non-ASCII (`é`, fullwidth digits, Cyrillic) and `uppercased()` maps `ß→SS`, `ı→I` (reviewer, verified): text parsing must be ASCII-only.

## Format (normative; copied into `docs/spec/license.md`)

**Payload, format version 1, big-endian:**

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | format version = `1` |
| 1 | 1 | signing key id (which trusted public key verifies it); `0` = the published test key |
| 2 | 8 | license key id (random); **the identity of a license** (revocation, ledger, support). Written as 16 lowercase hex characters |
| 10 | 2 | issued: whole days since 2026-01-01 **UTC** |
| 12 | 2 | updates until: days since 2026-01-01 UTC, **inclusive**; `0` = for life; otherwise ≥ issued |
| 14 | 1 | seats (informational) |
| 15 | 4 | products, 32-bit mask: bit 0 `optimer`, 1 `steady`, 2 `space`, 3 `devbox`, 4 `power`, 5 `tune`, 6 `guard`. **Verifiers ignore bits they do not know**, so adding a product is a minor Kit release and older apps still accept newer suite keys |
| 19 | 1 | licensee length *n*, 1–64 |
| 20 | *n* | licensee: UTF-8, NFC-normalised by the issuer; decoded strictly (invalid UTF-8 = malformed), never re-normalised |

Total length is exactly **20 + n** bytes of payload plus **64** bytes of signature (**84 + n**); anything else is malformed.

**Versioning:** the issuer always writes the lowest version that can express the license; a verifier refuses any version it does not know ("This key needs a newer version of the app"). A field that old verifiers must not ignore needs a new version.

**Signature:** ECDSA P-256, SHA-256, over the ASCII bytes `AMBYSTO-LICENSE-1` followed by the payload; 64 bytes raw `r‖s`, each half left-padded to 32 bytes. High-S signatures are accepted on every platform (CryptoKit does). Two texts can encode the same license, so **nothing may use the text or a hash of it as an identity**: the license key id is the identity.

**Text:** `AMB-` + Crockford Base32 of `payload ‖ signature`, upper case, groups of five joined by `-`, no check symbol. Parsing, **ASCII only**:
1. strip a leading `AMB` (any case) and one following `-` if present;
2. ignore `-`, space, tab, CR, LF; any other character outside `0-9 A-Z a-z` → malformed;
3. upper-case ASCII; map `O→0`, `I→1`, `L→1`; `U` → malformed;
4. lengths whose remainder mod 8 is 1, 3 or 6 → malformed; the unused trailing bits must be zero, otherwise malformed.

**File:** `.ambystokey` = the text in UTF-8 with an optional final newline, at most 4 KB; UTI `com.ambysto.license-key`, conforming to `public.data` (not plain text, so TextEdit does not claim it).

**Verification order:** text → bytes → exact length → known version → licensee UTF-8 → known signing key id → signature → revoked license key id. One plain reason string per failure.

**Compromised signing key:** remove its id from the trusted set in the next Kit release and re-issue every license in the ledger with a new key id (spec section "Rotation").

## Files (in build order)

Branch `aps-10-kit-license` → PR → `main`. Commit messages end with the Co-Authored-By line.

### 1. Spec — `docs/spec/license.md`, `docs/spec/license-test-vectors.json`
- The format above, the product registry, versioning, rotation, revocation, the file, the reason strings.
- Windows note: `ECDsa.Create()` + `ImportParameters` with `Q.X`/`Q.Y` from the raw public key; `VerifyData(message, signature, HashAlgorithmName.SHA256, DSASignatureFormat.IeeeP1363FixedFieldConcatenation)`; strict UTF-8 (`new UTF8Encoding(false, true)`).
- The **test signing key** (id 0), private and public halves in hex, labelled "published on purpose; never trusted by release builds".
- Vectors: each has the text, the payload hex, the signed message hex, `r‖s` hex, the trusted keys and revocation set used, and the expected result. Cases: valid single app; valid suite; valid with `updatesUntil`; Vietnamese licensee with diacritics; lowercase + spaces + line breaks; `O/I/L` substitutions; a signature whose `r` starts with `0x00`; the high-S twin of a valid signature (valid); unknown product bit 20 set (valid; covers only known products); tampered payload byte; tampered signature byte; unknown signing key id; revoked key id; version 2; wrong length; invalid UTF-8 licensee; non-zero trailing bits; `#` and a non-ASCII digit in the text; empty.

### 2. Package — `Package.swift` (swift-tools 6.0, macOS 14, Swift 6)
- Library product `AmbystoLicense` (target `AmbystoLicense`).
- Executable product `ambysto-license` (target `LicenseTool`, plus C target `KeychainACL`). Not a dependency of any app.
- Test target `AmbystoLicenseTests`. No third-party dependencies. `.gitignore` adds `*.dmg`, `*.ambystokey`, `ledger*.csv`.

### 3. Library — `Sources/AmbystoLicense/`
- `Product.swift` (registry, bits, ids); `Base32.swift` (rules above); `LicensePayload.swift`; `License.swift` (`covers(_:)`, `allowsUpdates(builtOn:)` with UTC day comparison, inclusive); `LicenseError.swift`; `LicenseVerifier.swift` (`init(trusted: TrustedKeys = .production, revoked: Set<String> = Revocations.all)`, `verify(_ text:)`, `verify(fileAt:)` with the 4 KB limit); `Revocations.swift` (empty in 0.1.0); `LicenseSigner.swift` (`package` access: the tool and tests only).
- `TrustedKeys.swift`: `.production` (id 1, filled at release, group 7) is public; `.test` (id 0) has **`package`** access, so the tool can use it in release builds and apps cannot.

### 4. Tool — `Sources/LicenseTool/`, `Sources/KeychainACL/`
Run by the owner as a **release binary built from a reviewed tag, in a clone only the owner's user can write** (never `swift run` in a checkout an agent can modify). External tools are called by absolute path (`/usr/bin/hdiutil`). stdout carries only what the command produces (a license, a public key, yes/no); every reminder goes to stderr.
- `new-signing-key [--id 1] --backup /Volumes/<external drive>/ambysto-signing-key.dmg` — refuses if a key already exists; refuses a backup path on the Mac's own disk, inside a git work tree or a cloud folder; asks for a passphrase twice with no echo (`readpassphrase`, at least 12 characters), writes it to `hdiutil` **without a terminator**; creates the AES-256 image; attaches with `-owners on -nobrowse` at a mountpoint inside a fresh `0700` folder owned by the owner; writes the key file with mode `0600`; detaches on every exit path (normal, error, Ctrl-C); stores the private key through `SigningKeyStore`; prints the public key in hex.
- `import-signing-key <image>` — same mount rules, read-only; stores through `SigningKeyStore`.
- `issue --licensee <name> --products space[,optimer…] [--seats 3] [--updates-until YYYY-MM-DD]` — rejects names with control or bidi characters or over 64 bytes (never truncates); NFC-normalises; reads the key (macOS asks for the login password); signs; verifies the result with `LicenseVerifier`; **appends the ledger line and `fsync`s before printing** the key; writes `<keyid>.ambystokey` next to the ledger.
- `backup-ledger <image>` — copies the ledger into the backup image (same mount rules), so revocation survives a lost Mac.
- `public-key`; `scan-for-key <repo path>` — reads the key in memory and searches the work tree and full git history for its hex, base64 and raw forms; prints only `found` or `not found` (Proof 3).
- `test-vectors --out <file>` — test key only.
- Ledger: `~/Library/Application Support/Ambysto License/ledger.csv`, mode `0600`, every field quoted, fields starting with `= + - @` prefixed with `'`.
- `SigningKeyStore` is the one storage step. `KeychainStore`: the **file-based login keychain**, never `kSecUseDataProtectionKeychain` (that keychain ignores this ACL and an ad-hoc CLI gets `errSecMissingEntitlement`); added with an empty trusted-application list via `KeychainACL.c`; read with `SecItemCopyMatching`. Without a GUI session (for example over SSH) the read fails with `errSecInteractionNotAllowed`, reported as "Run this in a logged-in session on the Mac; macOS must ask for your password." `FileStore` exists only in DEBUG builds and refuses any signing key id other than 0.
- The private key never touches stdout, stderr, argv, environment, temporary files or logs; it lives in memory only while signing.

### 5. Tests — `Tests/AmbystoLicenseTests/`
- Every vector gives its documented result (criterion 1).
- Round trip and the text rules: lowercase, separators, `O/I/L`, non-ASCII rejected, trailing bits, invalid lengths (criterion 4).
- Fuzz: 20,000 random strings never crash; 20,000 single-byte mutations of the **decoded bytes** of a valid key never verify (criterion 3).
- Products: known bits only; suite key covers each listed product; `allowsUpdates(builtOn:)` at, before and after the inclusive day; for life allows any date.
- `.production` has no id 0; a test-key license fails with `unknownSigningKey` under `.production`.
- Timing under 10 ms (criterion 6).
- Tool with the DEBUG `FileStore` and the test key: an issued key verifies; the ledger line exists before stdout is written; stdout contains only the license.

### 6. Release (owner + agent) — order matters
1. Merge groups 1–5 by PR.
2. Owner, on the issuing Mac, in an owner-only clone at the merged commit: `swift build -c release`, run `new-signing-key` with the backup on a USB drive.
3. A PR adds the printed public key to `TrustedKeys.production`; merge.
4. Tag that merged commit `v0.1.0` on `main`; the tag is never moved (a fix is `0.1.1`).

### 7. Space adoption (in `ambysto/ambysto-space`, after the tag, its own PR)
- `Package.swift`: the Kit dependency on the **`SpaceCore`** target (`from: "0.1.0"`, product `AmbystoLicense`).
- `KitLicenseVerifier` adapts `LicenseVerifier` to Space's `LicenseVerifying` seam, using module-qualified names (`AmbystoLicense.License`) to avoid the clash with Space's own `License`; becomes `EntitlementStore`'s default; `PendingLicenseVerifier` is deleted.
- A key that does not cover Space is refused with the apps it does cover ("This key is for Ambysto Optimer"). A suite key activates only the app that opened it; each app is activated separately.
- `Info.plist`: imports `com.ambysto.license-key`, document type `.ambystokey` with `LSHandlerRank` = `Owner`. With several Ambysto apps installed, macOS picks one to open the file; that app explains the key if it does not cover it. Each app imports the UTI (the Kit owns the definition in its spec).
- Proof needs the built app registered with LaunchServices (installed in `/Applications`, or `lsregister`).

## Risks

| Risk | Catch |
|---|---|
| A coding agent modifies the tool or its build before the owner runs it | Release binary from a reviewed tag in an owner-only clone; agents run under a separate user that cannot write there; absolute paths for system tools. |
| The private key leaks (output, argv, temp files, mounted backup) | stdout/stderr discipline; `readpassphrase`; `-owners on`, `0700` mountpoint, `0600` file, detach on every path; backup only on an external drive; `scan-for-key` (Proof 3). |
| A coding agent reads the Keychain item | Empty trusted-application list → password prompt on every read; "Always Allow" would trust the tool, so the tool warns on stderr to choose "Allow", and Proof 8 checks that a second `issue` asks again. |
| The backup cannot be opened by hand | Passphrase written without a terminator; Proof 9 opens it by double-click in Finder. |
| Newer suite keys refused by older apps | Unknown product bits ignored; new fields need a new version, which old apps refuse with a clear message. |
| Swift and .NET parse text differently | ASCII-only rules, strict UTF-8, vectors with raw hex and an `openssl` check (Proof 4). |
| Release builds trust the test key, or the tag precedes the production key | `package` access; tests on `.production`; group 6 order; Proof 7 checks `.production` at the tag. |
| Ledger lost or corrupted | `fsync` before printing; quoting; `backup-ledger` into the encrypted image. |
| A secret lands in the public Kit repo | The repo holds only public material by design; `scan-for-key` and a history scan before every release. |
| Several apps claim `.ambystokey` | One handler wins; the receiving app names the apps a key covers. |

## Proof

1. `swift build -c release` in the Kit: 0 warnings.
2. `swift test`: all pass (vectors, text rules, fuzz on decoded bytes, products, test-key boundary, timing).
3. **Owner:** `ambysto-license scan-for-key <Kit repo>` and `<Space repo>` print `not found`.
4. Every valid vector also verifies with `openssl dgst -sha256 -verify` after converting `r‖s` to DER (a short script in `scripts/`), including the `r` with a leading zero byte.
5. Development issuing with the DEBUG `FileStore`: an issued key verifies; the ledger line is written first; stdout has only the license.
6. `docs/spec/license.md` has no Swift types outside "macOS note" lines; the Windows note names the .NET calls.
7. **Owner + agent:** release steps of group 6 done; `TrustedKeys.production` is non-empty at `v0.1.0`; Space builds against `from: "0.1.0"` with all tests green.
8. **Owner:** `issue` asks for the login password; cancelling makes it fail with nothing on stdout; a second `issue` asks again.
9. **Owner:** the backup opens by double-click in Finder with the passphrase; `import-signing-key` on a second Mac or a fresh user restores the key; a license issued there verifies.
10. **Owner + agent:** Space Proof 12 with Wi-Fi off: a `space` key and a suite key unlock Pro without a restart; an `optimer` key is refused naming Optimer; double-clicking an `.ambystokey` file opens Space and activates it.
11. Independent review of the diff against the intent and this plan.

## Repository visibility (owner decision, 2026-10-10)

`ambysto/ambysto-kit` is **public**: it holds no secrets (only public keys, the spec and code), so Space and later apps build on any machine, including the agents' user on the Mac Studio, without GitHub credentials. Before the switch, the full history was scanned: no tokens, keys or passwords. Every later change to this repo must keep it that way (`scan-for-key`, Proof 3).

## Out of this plan

Everything in the intent's Out of scope, plus: Optimer adopting the Kit (AO-5 follow-up), a .NET verifier, and any change to Space beyond group 7.
