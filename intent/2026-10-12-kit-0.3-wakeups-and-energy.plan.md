# Plan — Ambysto Kit 0.3: wakeups and energy per process

Intent: [`2026-10-12-kit-0.3-wakeups-and-energy.md`](2026-10-12-kit-0.3-wakeups-and-energy.md) (approved 2026-10-12 with two owner decisions). Self-contained: an implementing agent reads this file and the intent only. Not yet accepted by the owner; an independent review follows before that.

**Consumer:** Ambysto Power plan group 6 (`ambysto-power`, `intent/2026-10-11-ambysto-power-macos-v1.plan.md`, "Power by app"): it sums per-interval deltas (CPU nanoseconds, idle wakeups, billed energy) over an app's processes and over 5-minute and 1-hour windows. The shape below is the one written into `ambysto/ambysto-kit#18` after Power's technical review.

## Architecture

All changes are in `AmbystoProcess`, its tests, `docs/spec/process.md` and `ProcessProbe`, so the release-line cherry-pick onto `release/0.2` applies cleanly (no suite bar file is touched).

```swift
// ProcessReader.Usage — three more counters from the same rusage_info_v4 call (no new system call)
public var idleWakeups: UInt64        // ri_pkg_idle_wkups
public var interruptWakeups: UInt64   // ri_interrupt_wkups
public var billedEnergy: UInt64       // ri_billed_energy, raw kernel units (undocumented; deltas and shares only)
public init(footprint:cpuTicks:diskRead:diskWritten:idleWakeups: = 0, interruptWakeups: = 0, billedEnergy: = 0)

// New: what changed between two samples of the same identity
public struct UsageDeltas: Sendable, Equatable {
    public var interval: UInt64          // nanoseconds between the two samples (sampler clock)
    public var cpuNanoseconds: UInt64    // ticks converted through MachClock
    public var idleWakeups: UInt64
    public var interruptWakeups: UInt64
    public var billedEnergy: UInt64      // 0 stays 0 (decision 1)
    public var diskRead: UInt64
    public var diskWritten: UInt64
}

// ProcessUsage — additions, all defaulted in the public initialiser
public var deltas: UsageDeltas?                 // nil on the first sample and when any counter went down (decision 2)
public var idleWakeupsPerSecond: Double?        // from deltas, same nil rule
public var interruptWakeupsPerSecond: Double?
```

**Sampling rule (spec "Sampling", HARD):** the sampler keeps the previous counters per identity (pid + start time, unchanged). For an identity seen in the previous sample, if **every** counter (CPU ticks, disk read, disk written, idle wakeups, interrupt wakeups, billed energy) is greater than or equal to its previous value and the elapsed time is above 0, it sets `deltas`, the CPU % and disk rates (as today) and the two wakeup rates; otherwise **all** of them are `nil` for that process in that sample. Today's rule for CPU and disk is the same rule with fewer counters, so a process that had a CPU value before may now lose it only when one of the new counters went down, which the kernel does not do for a live identity (counters are cumulative since process start).

## Files (in build order)

Branch `aps-12-kit-0.3-wakeups-energy` → PR → `main`; one commit per group; Co-Authored-By trailer.

### 1. Spec — `docs/spec/process.md` (main session; HARD: sampling rules)
- "A process record", usage row: add idle wakeups (times the process woke the CPU package from idle), interrupt wakeups, billed energy (the kernel's energy accounting; the unit is **undocumented**, so callers use deltas and shares, never a unit; 0 is reported as 0).
- "Sampling": per-interval deltas and the interval; the all-or-nothing rule above; wakeup rates per second.
- Windows note: no public per-process wakeup counter; energy estimates only through the system resource usage monitor (`powercfg /srumutil`), not per interval; a caller falls back to CPU time.
- macOS note: the three `rusage_info_v4` fields by name; the spike result (group 3) once recorded.

### 2. Reader, sampler, tests (builder, then reviewer; the reviewer checks the code against group 1)
- `ProcessReader.usage(_:)`: fill the three counters from the existing `rusage_info_v4`.
- `ProcessSampler`: `Counters` gains the three counters; the all-or-nothing comparison; `UsageDeltas` built from the same subtraction already done for CPU and disk; `interval` = the elapsed nanoseconds the sampler already computes.
- Tests (`Tests/AmbystoProcessTests/ProcessTests.swift`, suite "ProcessSampler"):
  - fake source, two samples with known counters and an injected clock → exact `deltas`, `interval`, wakeup rates;
  - first sample → `nil`; reused pid (new start time) → `nil`; **each** counter decreasing on its own → all `nil` (six cases);
  - billed energy 0 in both samples → `deltas.billedEnergy == 0`, not `nil`;
  - live: **this test process** runs a thread that sleeps 5 ms two hundred times and spins briefly between sleeps; two samples of this process's own identity show `deltas.cpuNanoseconds > 0` and `idleWakeups + interruptWakeups > 0`, and `interval` within 5 % of the wall time between the samples (intent criterion 1; the test reads its own process rather than spawning a helper, so it needs no interpreter on the machine — a clarification of "a spawned busy loop");
  - `PublicInitTests`: build `Usage`, `UsageDeltas` and `ProcessUsage` with and without the new arguments.

### 3. Probe and spike — `Sources/ProcessProbe/main.swift`, `scripts/energy-spike.sh` (builder)
- `ProcessProbe energy <seconds>`: two samples `<seconds>` apart; prints JSON: machine model (`hw.model`), CPU type (`hw.optional.arm64`), readable processes, how many have `billedEnergy` > 0 and the sum of energy deltas, sums of idle and interrupt wakeup deltas, the top 5 by energy delta (pid and name only, printed locally; nothing leaves the machine).
- `scripts/energy-spike.sh`: builds the probe, runs `energy 10` three times, prints PASS when the energy delta sum is above 0 (Apple Silicon expectation) and records "zero" otherwise without failing (Intel is a finding, not a failure). The owner runs it on the M1/M3 Pro and on the Intel MacBook; the results go into the spec's macOS note (group 1, amended).

## Risks

| Risk | Catch |
|---|---|
| A process loses its CPU value because a new counter went down | Counters are cumulative for a live identity; the six single-counter tests show the rule is intended; the reviewer checks the spec states it. |
| The energy unit is misread as joules by a caller | Spec says "undocumented, deltas and shares only"; no unit in names or docs. |
| Intel reports 0 energy | Decision 1: raw 0; the spike records it; Power's own fallback rule. |
| The live wakeup test is flaky on a loaded machine | Own-process thread with 200 sleeps gives hundreds of wakeups; assert only `> 0`; serialized suite. |
| Existing callers break | Every new field defaulted in public initialisers; criterion 4 builds DevBox and Power against the commit. |
| The cherry-pick drags suite bar files | Only `AmbystoProcess`, its tests, `process.md`, the probe and the spike script change; the pick PR lists the files. |
| The library gains forbidden calls | 0.2 grep list re-run on `AmbystoProcess` and `AmbystoSafety`. |
