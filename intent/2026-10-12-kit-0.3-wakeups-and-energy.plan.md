## Architecture

All changes are in `AmbystoProcess`, its tests, `docs/spec/process.md`, `ProcessProbe` and one new script, so the release-line cherry-pick onto `release/0.2` applies cleanly (no suite bar file is touched).

```swift
// ProcessReader.Usage — three more values from one proc_pid_rusage call (RUSAGE_INFO_V6, V4 fallback)
public var idleWakeups: UInt64        // ri_pkg_idle_wkups
public var interruptWakeups: UInt64   // ri_interrupt_wkups
public var energy: UInt64?            // ri_energy_nj, nanojoules; nil when only V4 answered (unavailable ≠ 0)
public init(footprint:cpuTicks:diskRead:diskWritten:idleWakeups: = 0, interruptWakeups: = 0, energy: = nil)

// New: what changed between two samples of the same identity
public struct UsageDeltas: Sendable, Equatable {
    public var interval: UInt64          // ns between the two samples: monotonic clock, time asleep excluded
    public var cpuNanoseconds: UInt64    // ticks converted through MachClock
    public var idleWakeups: UInt64
    public var interruptWakeups: UInt64
    public var energy: UInt64?           // nil when either sample lacked energy; 0 stays 0 (decision 1)
    public var diskRead: UInt64
    public var diskWritten: UInt64
}

// ProcessUsage — additions, all defaulted in the public initialiser
public var deltas: UsageDeltas?                 // nil on the first sample and when any counter went down (decision 2)
public var idleWakeupsPerSecond: Double?        // same nil rule
public var interruptWakeupsPerSecond: Double?
public var isZombie: Bool                       // from BSDInfo.status (Power's review note 8)
```

**Reading.** `ProcessReader.usage(_:)` calls `proc_pid_rusage(pid, RUSAGE_INFO_V6, …)`; if that fails with `EINVAL` (a kernel without V6) it calls V4 and leaves `energy` nil. Any other failure returns nil as today. One call per process in the common case; the fallback costs a second call only on such kernels.

**Sampling rule (spec "Sampling", HARD).** The sampler keeps the previous counters per identity (pid + start time, unchanged). For an identity seen in the previous sample, if **every** counter present in both samples (CPU ticks, disk read, disk written, idle wakeups, interrupt wakeups, energy) is ≥ its previous value and the elapsed time is > 0, it sets `deltas`, today's CPU % and disk rates, and the two wakeup rates; otherwise **all** are nil for that process in that sample. The interval is the sampler's existing clock (`DispatchTime` uptime), which does not advance while the Mac sleeps; callers that keep wall-clock windows must not mix the two. A process that starts and exits between two samples, and the last stretch of a process before it exits, are never counted: the spec states this undercount (short build steps vanish), and callers show "estimate".

## Files (in build order)

### 1. Spec — `docs/spec/process.md` (main session; HARD: sampling rules)
- "A process record", usage row: idle wakeups, interrupt wakeups, energy (the kernel's per-process energy estimate in nanojoules; *unavailable* on kernels without it, never shown as 0); zombie status in sampled records.
- "Sampling": deltas and the interval; the all-or-nothing rule; the interval is monotonic and excludes sleep; the short-lived-process undercount.
- Windows note: no public per-process wakeup counter; energy only through the system resource usage monitor (`powercfg /srumutil`), not per interval; a caller falls back to CPU time.
- macOS note: `RUSAGE_INFO_V6` with the V4 fallback, the field names, **why not `ri_billed_energy`** (the review measurement), and the spike results once recorded.

### 2. Reader, sampler, tests (builder, then reviewer; the reviewer checks the code against group 1)
- Reader as above; sampler: `Counters` gains the new values, the all-or-nothing comparison, `UsageDeltas`, `isZombie` from `bsd.status`.
- Tests, suite "ProcessSampler" marked **`.serialized`**:
  - fake source, two samples with known counters and an injected clock → exact `deltas`, `interval`, rates;
  - first sample → nil; reused pid (new start time) → nil; **each** counter decreasing on its own → all nil (six cases);
  - energy 0 in both samples → `deltas.energy == 0`; energy nil in either sample → `deltas.energy == nil`, other deltas present;
  - live: this test process runs a thread that sleeps 5 ms two hundred times with a short spin between sleeps; two samples of its own identity show `cpuNanoseconds > 0` and **`idleWakeups + interruptWakeups > 0`** (never idle alone: the review measured 200 interrupt and 16 idle wakeups), and `interval` lies between the clock readings taken just before the first `sample()` started and just after the second ended;
  - live energy (Apple Silicon only, skipped where `energy` is nil): the same busy span shows `deltas.energy > 0`;
  - `PublicInitTests`: build `Usage`, `UsageDeltas` and `ProcessUsage` with and without the new arguments; DevBox's and Power's existing call shapes (4-argument `Usage`, labelled `ProcessUsage`) compile.

### 3. Probe and spike — `Sources/ProcessProbe/main.swift`, `scripts/energy-spike.sh` (builder)
- `ProcessProbe energy <seconds>`: prints JSON: `hw.model`, Apple Silicon or Intel, whether V6 answered, readable processes, how many have energy > 0, the energy delta sum, idle and interrupt wakeup sums, **the probe's own energy delta over a one-second busy loop it runs**, and **per counter, how many identities went down** between the two samples. Nothing leaves the machine.
- `scripts/energy-spike.sh`: three runs of `energy 10`; PASS on Apple Silicon when the probe's own busy-loop energy delta > 0, the sum > 0 and no counter went down; on Intel it records the values (zero or unavailable is a finding, not a failure). The owner runs it on the M1/M3 Pro and on the Intel MacBook; results go into the spec's macOS note in a follow-up commit (picked onto the release line too).

## Risks

| Risk | Catch |
|---|---|
| The energy field measures the wrong thing | Corrected to `ri_energy_nj`; the spike and a live test require the process's **own** busy loop to raise it. |
| V6 unavailable on some supported kernel (macOS 14) | V4 fallback, `energy` nil (not 0); Power's CPU-time fallback; the spike reports whether V6 answered. |
| A process loses its CPU value because a new counter went down | Counters are cumulative for a live identity (review: 13,242 sample pairs, 0 decreases); the spike counts decreases per counter on every machine. |
| Callers mix the monotonic interval with wall-clock windows | Spec states it; Power's plan is told. |
| Short-lived processes are missed | Spec states the undercount; callers label results "estimate". |
| The live wakeup test flakes | Own-process thread; assert idle + interrupt > 0; serialized suite; interval bounded by clock reads around the calls. |
| Existing callers break | New fields defaulted; proof 4 builds DevBox and Power against the commit. |
| The library gains forbidden calls | 0.2 grep list on `AmbystoProcess` and `AmbystoSafety`. |
