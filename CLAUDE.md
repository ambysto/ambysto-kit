# Ambysto Kit: the shared Swift package of the Ambysto Pro Suite (Plane APS, GitHub ambysto/ambysto-kit)

## What it is
Five libraries the suite apps import, one tool only the owner runs, and the suite-level documents (`intent/2026-10-09-ambysto-pro-suite.md`, the market research). This repo is public: nothing private goes into it, its commits, this file or `.claude/settings.json`. No third-party dependencies.
- `AmbystoLicense`: offline license keys (P-256 signatures, CryptoKit): `LicenseVerifier`, `TrustedKeys`, `Revocations`, `Product` bits. Reads a key string or a `.ambystokey` file (4 KB at most); no network.
- `AmbystoProcess`: process reading over libproc and sysctl: pid list, identity by pid + start time, path, cwd, argv, open and mapped files, listening TCP sockets, CPU and memory sampling (`ProcessSampler`, `MachClock`); since 0.3 also idle and interrupt wakeups, energy (`ri_energy_nj` through `RUSAGE_INFO_V6`, V4 fallback without energy; never `ri_billed_energy`), and per-interval `UsageDeltas` with the all-or-nothing rule. It never sends a signal.
- `AmbystoSafety`: the file-safety gate: never-touch list, canonical paths and firmlinks, identity of the item and every ancestor by device + inode, in-use check, Full Disk Access. It never deletes or moves anything; which folders an app may change comes from the app's `AllowedRootRule`.
- `AmbystoSuite`: the merged suite bar's cross-app contract (`docs/spec/suite-bar.md`, vectors in `suite-bar-vectors.json`): the catalog of seven apps (id `space` is shown as Lean since APS-17; Gate's id is `gate`, bundle id `com.ambysto.gate`, since APS-20, the one id changed before any release; ids are fixed from the first release), glance records and their validator, the safe store of the shared folder, the host lock (blocking `flock` in a thread), settings, and the pure state rules (active with hysteresis, own icon, rows). Foundation and Darwin only.
- `AmbystoUI`: the Terminal theme (APS-16: `Theme.Terminal` neutrals, `Theme.tone(_:)` one tone per app for identity only, never a state, radii, SF Mono through `Theme.mono`; `accent` and `secondary` follow the system appearance, only the suite bar's floating bar is always dark), the floating panel and `GlobalHotKey` (from Optimer), and `SuiteParticipant`, the one object an app creates to publish its glance, host the suite item when elected and bind `MenuBarExtra(isInserted:)` to `showsOwnIcon`. `SuiteBarDemo` is its proof helper (`--snapshot <dir>` renders the suite views to PNG in a temp-folder sandbox); no app depends on it.
- App Intents (APS-14): no library. `docs/spec/intents.md` (two kinds: **read**, on the app's allow-list, and **opens the app**, which only routes to the app's own confirmation step), `scripts/app-intents-metadata.sh` (the metadata build step an app's `build-app.sh` calls before signing; only Xcode `27A266a` is proven) and `scripts/app-intents-lint.py` (fails the build when an intent breaks the kinds). Each app declares its own intents; the Kit defines no intent types. Intents run only in a build signed with a team id, so apps ship them only in Developer ID builds (AO-6).
- **Windows (`windows/`, APS-23):** the .NET 10 library `Ambysto.Kit.License` (namespace `Ambysto.Kit.Licensing`): the same license verifier, built from `docs/spec/license.md` and its vectors alone, never from the Swift code. `LicenseVerifier` (`Verify`, `VerifyFile`), `License`, `LicenseResult`, `LicenseReason`, `Product`; `TrustedKeys` and `Revocations` are internal; the published test key lives only in the test project. No package reference; MSTest in the test project only (owner decision 2026-10-16). Shipped as a NuGet package on GitHub Packages from `windows-vX.Y.Z` tags on `main` (`.github/workflows/windows-release.yml`).
  APS-24 adds **`Ambysto.Kit.Safety`** (`net10.0-windows`, P/Invoke only, no package reference): the file-safety gate from `docs/spec/safety.md` (Windows sections), never from the Swift code. `SafetyContext`, `SafetyGate` (`Check`, `CheckRestoreDestination`), `FileFacts.Read`, `InUseChecker`, `IAllowedRootRule`, `RefusalReason` with the spec's messages; internal seams `IEnvironmentFacts` and `IRecycleBinPolicy` (tests only). It decides and never changes anything (`scripts/windows-choke-points.sh`). The test project holds the acceptance tests, written before the code by a separate agent (and, after Stryker, from a spec-only gap list; failing system queries through the internal fault seam `Internal/Faults.cs`), and a test Cloud Files provider (`tests/Ambysto.Kit.Safety.CloudFixture`).
  APS-39 adds **`Ambysto.Kit.Process`** (`net10.0-windows`, namespace `Ambysto.Kit.Processes` to avoid colliding with `System.Diagnostics.Process`, P/Invoke only, no package reference): process reading from `docs/spec/process.md` (Windows notes), never from the Swift code. `ProcessIdentity` (`(ProcessId, StartTimeTicks)`), `ProcessReader` (`ReadSnapshot`, `Read`, `ExecutablePath`), `ProcessSnapshot`, `ProcessRecord` (`Readable`, `Unreadable`), `ProcessCounters`, `ListeningSockets` (`ReadForReadableProcesses`, `ReadAll`), `ListeningSocket`, `SocketAddressFamily`, `SocketAddressClass`, `ProcessSampler` (`Sample`), `ProcessSample`, `SampledProcess`, `UsageDeltas`; internal seams `IProcessSnapshotSource`, `ITcpTableSource` and `IMonotonicClock` (tests only). It reads and never terminates, signals, suspends or spawns anything (`scripts/windows-choke-points.sh`). All three Windows libraries are packed from the same `windows-v*` tag.
- `ambysto-license` (`LicenseTool`, with the C target `KeychainACL`, which only adds a Keychain item whose ACL trusts no app): issues keys, keeps the ledger, backs the signing key up to an external volume. Owner only.

Dependents: DevBox and Optimer (pinned by revision, `9e8c470`; `v0.2.0` exists since 2026-10-25, and each moves to `from: "0.2.0"` in its own PR); Space and Optimer still carry vendored copies of the safety and Pro code and switch later. Apps depend by semver tag (`from:`) once one exists; until then they pin a `main` commit and move it deliberately.
Cost of a bug: a wrong gate deletes user data in every app of the suite; a wrong verifier locks out paying users or lets forged keys through; a mishandled signing key cannot be taken back. The bar: spec vectors, an independent review of every safety change, and no key material within an agent's reach.

## HARD: the main session does it directly, then an independent reviewer
- `windows/src/Ambysto.Kit.Safety`, its acceptance tests, its test fixtures and `scripts/windows-choke-points.sh`: the same as `AmbystoSafety` below, plus the Windows recoverability rules (Recycle Bin preconditions, cloud files, sync roots, long paths) and failing closed.
- `AmbystoSafety`, including any new public API in it: the gate's order of checks, `NeverTouch` (a new entry too: add-only by spec, but what it protects is a product decision), identity by device + inode of the item and its ancestors, add-only protection, the `@_spi(Testing)` seam, the `AllowedRootRule` contract (`refusal` and `restoreRefusal` are separate on purpose).
- `AmbystoLicense`'s verifier and its parsing (the 0.1 reviews found their issues there), the same in `windows/src/Ambysto.Kit.License`, `scripts/check-key-sets.py` and `.github/workflows/windows-release.yml`, `LicenseTool` and `KeychainACL`: key custody, the ledger (written and fsynced before a key is printed), the backup image, released-id refusals.
- The license format, `docs/spec/license.md` and its vectors: Windows shares the format, a format change is a major version, `Product` bits never change (a new product is a minor release). The only vector generator is the tool's `test-vectors` command, which an agent never runs.
- `TrustedKeys.production`, `Revocations`, and tags: a tag is never moved. **Two copies:** the Swift and the .NET production keys and revocations must stay equal; the key PR and every revocation PR edit both, as two commits (only the Swift one is cherry-picked onto `release/0.2`; `windows-v*` tags are cut on `main`), and `scripts/check-key-sets.py` must pass before any tag.
- The suite bar contract: `docs/spec/suite-bar.md`, its vectors, `Sources/AmbystoSuite` (validator limits, freshness, hysteresis, host election, own-icon rule). Every Ambysto app relies on it, and Windows reimplements it; a change bumps the contract or the Kit version.
- The intents safety rule: `docs/spec/intents.md` (the kinds, the confirmation token bound to the shown items, the quit rule after a cold launch) and `scripts/app-intents-lint.py`. In an app, a new intent that changes something is HARD and must pass the lint; adding an intent to an app's read allow-list means reviewing that intent's code.
- The identity and sampling rules of `AmbystoProcess` and `windows/src/Ambysto.Kit.Process` (pid + start time; `exec` on macOS keeps both, so callers re-check the path; on Windows, pre/post handle `CreationTime`/`ExitTime` checks, parent validation against surviving snapshot entries, readable vs unreadable rule for elevated/other-user processes, and the all-or-nothing counter rule): DevBox's stop logic and Optimer/Power/Tune's sampling rely on them.

## Rules
- Building starts only after the owner has approved the intent and accepted the plan (the intent → plan → build → verify chain in `intent/`).
- The libraries never delete, move, spawn or signal. The grep list in the 0.2 plan (`trashItem`, `removeItem`, `unlink`, `kill(`, `killpg`, `Process(`, `posix_spawn`, …) stays at zero hits in `Sources/AmbystoProcess` and `Sources/AmbystoSafety`; `AmbystoLicense` has no network. Deleting and spawning exist only in `LicenseTool`. The suite bar plan's longer list (adds `moveItem`, `replaceItem`, `remove(`, `rename(`, `pthread_kill`, `sigqueue`, `proc_terminate`, `terminate(`, `forceTerminate`, `NSTask`, `system(`, `popen`, `NSAppleScript`) stays at zero hits in `Sources/AmbystoSuite` and `Sources/AmbystoUI`; the one exception is `NSWorkspace.openApplication` in the "Ambysto apps" list. Glances carry numbers and states only: every app's adoption is reviewed for names in labels, which no validator can catch.
- Never run the license tool from an agent: no `swift run`, no `.build/*/ambysto-license`, no `security` or `hdiutil` commands. The owner builds it in an owner-only clone under their own macOS user, whose login Keychain holds the key; agents run under a separate standard user that never sees that Keychain (the deny list in `.claude/settings.json` is a tripwire; that separation is the real protection). The owner creates the signing key with a USB backup, and only the printed public key enters the repo (a PR adds it to `TrustedKeys.production` and updates the test that pins `production.ids`). `*.ambystokey` and `ledger*.csv` are gitignored; a key is never committed and never pasted into chat (if one is, it is rotated).
- The test key (id 0) is published on purpose and is never trusted by release builds. Apps cannot mint keys (`package` access), so they test entitlement through their own verifier seam.
- Protection is add-only: an app may add protected roots, never remove one; `@_spi(Testing)` is for tests.
- Public API serves the apps: records stay constructible (public initialisers, ambysto-kit#16) and `Sendable`; a breaking change bumps the major version and every app's pin.
- Vendored code keeps its "From Ambysto Space (…)" / Optimer headers; the apps are told when the Kit owns the code and switch in their own PRs.
- Never silently change a never-touch entry, a protected suffix, a vector or a revocation. Flag it and ask; owner decisions live in the intents and plans.
- Gift keys are for life and launch is on gifted keys; a key is never tied to writing a review.
- Git and tickets: English only; the `ambysto` account (check with `gh api user --jq .login` before the first PR of a session; if it is not `ambysto`, stop and ask; never `gh auth switch`); repo-local author `Ambysto`; branches `aps-NN-slug`, never a push to `main`; one commit per plan group, one PR per plan (or per fix); commits "Summary (APS-NN, plan group N)", with no Co-Authored-By trailer and no "Generated with" line (owner decision 2026-10-20: contribute only as Ambysto); do not merge without being asked. Plane APS: use the `plane` MCP when the session has it (configured per user, outside this repo); otherwise its REST API. The host, workspace and project id are in the gitignored `CLAUDE.local.md` on the owner's machine (this repo is public), and the key is read at run time from `~/.claude.json`, never printed. Cross-link GitHub issue and PR with the Plane item.
